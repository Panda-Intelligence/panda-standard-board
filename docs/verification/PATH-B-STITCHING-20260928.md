# 路径 B 执行结果：跨槽缝合（2026-09-28）

**结论：缝合是可行的,但结构上很弱 —— 不建议把它当作 In1 问题的"解法",只能算"缓解"。**

理由是执行中量出来的一个硬事实:In1 上的信号走线两侧**本来就没有 GND 铺铜** —— 铺铜被净空规则
从信号旁边排开了,而**那个"被排开"就是槽本身**。所以"贴着信号补缝合过孔"在多数位置**无铜可连**。

## 一、执行与迭代记录（每一步都用原生 DRC 验收）

工具：`.local-thin18-in1opt/stitch_in1.py` —— 沿 In1 信号段按 4mm 采样,在两侧 ±0.6…1.8mm 找
合法位放 GND 过孔（0.4/0.2,与全板一致）。合法性最初用 0.1mm 栅格（焊盘/走线/过孔 +0.25mm 净空）。

| 迭代 | 修的问题 | 结果 |
|---|---|---|
| v1 | 仅"中心格"合法即放 | **849 违规**（clearance 290 / hole 200 / **shorting 171** / edge 74 / dangling 113）,unconnected 0→106 ✗ |
| v1.5 | 加非 GND 铺铜约束（仍用包围盒近似外形） | 908 ✗（更差,说明外形模型错） |
| v2 | **过孔按全径+净空判邻域**（原来是"中心格"判定 ✗） | **207**（shorting 171→**13** ✓ 一举干掉 158 个） |
| v3 | **外形沿真实 Edge.Cuts 密集采样** + **只在该处确有 GND 铺铜时才放**（纯 python 射线法,因 KiCad 的 python 无 shapely） | **23**（clearance 7 / hole 7 / shorting 2 / dangling 7）,**unconnected 回到 0** ✓ |

**可行缝合位从 267 → 24 个** —— 关键就是这个落差：**铺铜不在信号旁边**。

---

## 二、为什么缝合弱（本质原因）

- In1 的 GND 铺铜与 In1 上的信号走线之间必须满足净空（0.2mm 起）→ 铺铜被"挖开" ✓
- 这个被挖开的区域**就是回流路径的槽** ✓
- 想在信号旁边放缝合过孔 → 落点正好在**无铜的挖空区** → 该过孔悬空（dangling ✗）
- 强行放宽（把过孔放进挖空区并让铺铜重新流进去）→ 需要铺铜**贴着信号**重新填充,而那会**违反净空** ✗

**所以"接受 + 缝合"这条路对 In1 是自相矛盾的**：能缝合的位置,恰恰是不需要缝合的位置。

## 三、当前状态与建议

**已做**（可复现,工具与脚本都在 `.local-thin18-in1opt/`）：
- 缝合工具 + 三次迭代 + 每步的 DRC 数字（本文件表格）
- 缝合候选 24 个 / 最优 DRC 结果 23 违规（**未通过验收** ✗,故**未固化为检查点**）

**建议改走"人工定向重布"**（这才是真解）：
1. 优先对象：**I2C_SCL（108.4mm / 21 段,平均 5.16mm）与 EXP_INT（92.5mm / 25 段,3.70mm）**
   —— 只有这两条是"长距离真占用平面"；其余（EPD16_CS/VGL、I2S_LRCLK、UART0_RX）是 0.3–0.8mm 的过路短跳,影响有界；
2. 方法：逐段把 In1 上的连续走线改到 F/In2/B（层数足够 —— 全板非开窗区还有 39% 空闲）；
3. 验收：仍是四道门（0 违规 / 0 parity / unconnected 不增 / 无回归）+ 出 `routingNNN` 检查点。

**若不做**：应在设计记录里明确写"**In1 参考面被 1,224mm 信号穿越,未做 SI/EMC 缓解**",不要把它当成已缓解。

## 五、补充：第三种方法（定向重布）也失败 —— In1 问题正式收口

2026-09-28 16:14 追加。为验证"人工定向重布"是否可行,直接调用**能用的光栅路由模块**
（`raster_router.Geometry.route()` —— 它只计算路径、不写板子,输出 `route.json`）,对撕掉 In1 段后的
I2C_SCL（8 条待布连接）在 **F.Cu / In2.Cu / B.Cu 三个信号层**上求解：

```
BUILD I2C_SCL groups 2 width 0.2 step 0.1
group 0: start=... goal=... visited=420166 NO_PATH
group 1: start=2131 goal=1122 visited=420166 NO_PATH
=> diagnostic.json status = no_grid_path
```

**至此三种方法全部失败,且互相独立**：

| 方法 | 引擎 | 结果 |
|---|---|---|
| ① FreeRouting 单网（走他们的清单机制） | freerouting 2.4.1 | 16 轮 score 0.00,无改善 ✗ |
| ② 跨槽缝合（路径 B） | 自建 | 可行位 267→24,且本质自相矛盾 ✗ |
| ③ 定向重布（光栅 A*） | grid_path（4 层求解器） | 420k 格搜索,NO_PATH ✗ |

**结论（证据充分）**：在当前布局下,**I2C_SCL 的 In1 段无法重布** —— 三个信号层里没有可用的通道,
不是算法问题。剩下的唯一真解是**布局变更**（把 J802 带/中段的低针脚小件迁往顶带那 761 mm² 空闲区,
创造出通道容量）,即评审里的 P1-2。

## 六、给打样决策的最终建议

1. **EVT-1 照常打样**（Gerber 来自 `routing142`,与本调查无关 ✓）—— 打样的目的本来就是**测量**;
2. 板子回来后**实测高速信号完整性**（I2C 400kHz / SDMMC / USB / I2S）,把 In1 参考面被穿越的
   实际影响**量化出来**,作为下一版的输入;
3. **EVT-2 之前做 P1-2 布局再平衡**（可动清单已备:16 个 / 63.1 mm²,其中 14 个在 J802 带内）,
   让通道容量出现后,再重布 In1 信号 —— 那时才是"能解"的状态;
4. 设计记录里必须写明:**In1 参考面被 1,224 mm 信号穿越,未缓解**,不要当成已处理。
