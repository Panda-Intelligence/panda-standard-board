# Panda 標準電子書板：符號與封裝規則

工作包：WP0（工具鏈與受控輸入）
日期：2026-08-10
狀態：規則已凍結；TPS63802DLA 符號已進入 A 階段建立，全部封裝與獨立複核仍未完成（屬 WP4／WP5）

本文件落實 PRD R4：每個自建符號／封裝必須以受控資料手冊逐 pin 複核，並由**不同身份**執行封裝尺寸、
焊盤、Pin 1、FPC 方向與 3D／機構高度檢查。供應商下載的 CAD 只能作為**輸入**，不能免除複核。

## 1. 專案庫命名

| 用途 | 路徑 |
| --- | --- |
| 專案專用符號 | `lib/panda-standard.kicad_sym` |
| 專案專用封裝 | `lib/panda-standard.pretty/` |

這兩個名稱由 design.md §7 指定。WP0 只凍結命名與規則，**不建立**符號／封裝檔案本身；實際工作分為：
A）WP4／WP5 建立資產並記錄 builder，建立後才產生 identifier／SHA-256；B）不同身份逐 row 複核實際 hash；
C）只有 A+B 完成的資產才可放置／接線。不得要求尚未建立的資產預先提供 hash，也不得以此跳過 B。

3D 模型若需專案自有件，放在 `lib/panda-standard.3dshapes/`，並在封裝內以相對路徑引用，不得指向使用者
主目錄或應用程式套件內的絕對路徑。

## 2. 何時可直接用官方庫，何時必須自建

### 2.1 可直接使用官方庫

- 無源器件的通用 IPC 封裝（0402／0603／0805 電阻電容、標準電感封裝）；
- 通用 SMD 半導體封裝（SOT-23、SOD-323、標準 QFN／WSON，且與資料手冊尺寸逐項相符）；
- 通用符號（電阻、電容、電感、二極體、測試點、接地／電源符號）。

即使使用官方庫，仍必須完成 §3 的資料手冊逐項核對；官方庫是**候選**，不是免檢通道。特別注意：官方
通用封裝的散熱焊盤（thermal pad）、防焊開窗與過孔陣列常與具體器件資料手冊建議不同，必須逐項對照。

### 2.2 必須自建（或以官方庫為基礎另存為專案件）

- 所有主動器件的符號，因為 pin 功能、NC／DNU、裸露焊盤與電源腳分組必須與精確訂貨號一致；
- ESP32-S3-WROOM-1-N16R8 模組（含天線 keepout 區的機構邊界）；
- 所有 FPC／連接器（顯示、觸控、前光、電池、扬聲器、板間連接器），因為接觸面方向與 Pin 1 決定裝配
  正確性；
- microSD 卡座、USB-C 連接器；
- 無外露連接器的六網彈簧針／Tag-Connect 相容焊盤（`UART0_TX`、`UART0_RX`、`EN`、`GPIO0`、`3V3`、`GND`）；
- 任何官方庫尺寸與受控資料手冊不符的器件。

## 3. 強制複核清單（每個器件逐項執行）

每個進入原理圖／PCB／BOM 的 row（含 DNP、連接器、無源、測試點與機構特徵）都必須完成下列全部項目並留下
記錄。不得只抽查高風險 IC 或按「同封裝類別」簽一次總表：

### 3.1 符號逐 pin 複核

- [ ] 精確訂貨號與資料手冊版本／日期已記錄；
- [ ] 逐 pin 對照 pin 編號、名稱、電氣類型（power in／out、passive、input、output、bidirectional、
      unspecified）；
- [ ] NC 與 DNU 明確區分：DNU 不得接地或併入網路；
- [ ] 裸露焊盤／散熱焊盤的電氣歸屬（接地或懸空）與資料手冊一致；
- [ ] 多電源腳（例如 VDD／VDDIO）未被錯誤合併為單一 pin；
- [ ] 隱藏 pin 為零：所有電源／接地 pin 必須顯式可見並顯式連線。

### 3.2 封裝獨立檢查

- [ ] 封裝外形尺寸、焊盤尺寸與間距對照資料手冊建議 land pattern；
- [ ] Pin 1 標記在絲印與 3D 上一致，且與符號 pin 1 對應；
- [ ] FPC／連接器的接觸面朝向（正面接觸或背面接觸）與插入方向已標註；
- [ ] 3D 模型存在，且機構高度（含連接器插合高度）與資料手冊一致；
- [ ] 阻焊、鋼網開口與散熱過孔符合器件建議與板廠能力；
- [ ] 器件朝向標識（IMU 的 X／Y／Z）在絲印上明確。

### 3.3 獨立性要求

上述 symbol 逐 pin 與封裝檢查必須由**不同於建立者的第二身份**執行，並記錄實作者、複核者與日期。
實作者延後再看、換一個代理名稱、同一身份另開 session，均不構成獨立複核。實作者不得自簽。每一個逐項結果
都要有 evidence；總表或總簽名不能把空白逐項證據改成通過。

## 4. 供應商 CAD 的處理邊界

供應商或第三方（含 SnapEDA、Ultra Librarian、板廠提供的庫）下載的符號／封裝：

- 只能作為**輸入**匯入專案庫，且必須另存為專案件（`panda-standard.*`），不得直接引用外部庫路徑；
- 必須完整重跑 §3 全部複核項目；
- 必須記錄來源 URL／檔名、下載日期與原始檔案校驗值；
- 已知風險：第三方庫常見 pin 順序錯誤、land pattern 過小、Pin 1 標記錯位與缺少散熱焊盤，因此
  「有官方 CAD」不能作為跳過複核的理由。

## 5. 複核記錄要留什麼

每個器件在 `lib/` 旁保留一筆複核記錄（建議 `lib/review/<訂貨號>.md`），內容至少包含：

| 欄位 | 說明 |
| --- | --- |
| 精確訂貨號 | 含封裝後綴，不使用系列名 |
| 資料手冊 | 版本／修訂、日期、來源（受控檔案路徑或供應商連結） |
| 符號來源 | 官方庫名稱、供應商 CAD 來源，或自建 |
| 封裝來源 | 同上 |
| Project identity | symbol/footprint library identifier、檔案路徑、各自 SHA-256、source commit |
| 逐 pin／pad 複核 | builder 身份、不同 reviewer 身份、日期／時區、逐項 evidence |
| 封裝獨立檢查 | 尺寸／焊盤／Pin 1／FPC 方向／3D 高度、reviewer（須不同於建立者） |
| 差異 | 唯一 difference ID、處置 commit、closure evidence；未關閉不得簽過 |
| 例外 | 任何偏離資料手冊建議的決定，含原因與證據 |

精確 BOM 未凍結時，允許保留「待精確料號後生成受控附表」，但該狀態明確**阻塞總簽名**；禁止用佔位封裝或
空白簽名列代替。沒有完整逐 row 複核記錄的器件／無源／機構件不得進入 ERC 通過聲明或製造輸出。
Symbol／footprint 子門即使完成，也不能替代
原理圖、ERC、板廠 stackup／DFM、機構批准、WP6A 或 WP7A 的其他獨立門。

## 6. 與其他工作包的關係

- WP4／WP5 的 A 階段建立符號與封裝時執行本規則；B 階段由不同身份依實際 hash 複核；
- WP4／WP5 原理圖放置／接線只可使用通過 A+B 的資產，且仍受相應模擬／台架 gate 約束；
- WP6A／WP6B 預 Layout 審查確認複核記錄齊備；
- WP8 產生製造輸出前，必須確認每個 BOM 行都有對應複核記錄。
