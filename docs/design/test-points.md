## 1. 分區原則（凍結）

| 分區 | 位置 | 內容 | 探測方式 |
| --- | --- | --- | --- |
| **TP-LV-CORE** | 核心板 | 低壓電源、地、I²C、關鍵時序、中斷、電源鍵 | 彈簧針（pogo）治具 + 手動探針 |

### 1.1 硬邊界

| 邊界 | 規則 |
| --- | --- |
| HV／VCOM 測試點**只**存在於轉接板受控區 | 核心板**無**任何高壓測試點 |
| HV 測試點**不得**與 LV pogo 治具區共用或相鄰 | pogo 治具接觸面上不得出現任何高壓網路 |
| HV 區與 LV pogo 區須有明確絲印與間距分隔 | 防止治具誤觸 |
| pogo 治具**不接觸**轉接板 | 治具只服務核心板底面 |

**理由**：pogo 治具是產線／返修可重複、可能由非工程人員操作的接觸面。任何高壓網路出現在該面上都是
人員與設備風險。`design.md` §3 已要求「高壓測試點只在適配板受控區域」，本文件把它落實為分區與間距規則。

### 2.2 電流量測斷點（凍結為必備）

`design.md` §5 要求「可隔離電源域的測量斷點」。USB監控加入前的**歷史**計算包絡為36.45–40.45µA；

**40.25–44.25µA**，不是整板max。IMU、load-switch、板漏、實際DC狀態及尚未實現的RTC後備仍待測，
未通過50µA門（[power-tree.md](power-tree.md) §5.1）；逐域電流量測是
**達標判定的必要條件**，不是選配。

| --- | --- | --- | --- |
| MB1 | `BAT+` 串聯 | 0 Ω 0805 + 兩側焊盤 | 整板電流（深睡 µA 級判定） |
| MB2 | `3V3_AON` 出口串聯 | 0 Ω 0805 + 兩側焊盤 | 常供域合計；源側=`3V3_AON_SRC`，負載側=`3V3_AON` |

### 2.4 ⚠ 高速訊號測試點的約束

以下訊號**不設**專用測試點焊盤：

| 訊號 | 理由 |
| --- | --- |
| `USB_D+`／`USB_D−` | 90 Ω differential、pair skew ≤0.5 mm；測試點會破壞阻抗連續性，改由 USB-C 座端或治具側量測 |
| `EPD_D0–D7`、`EPD_CKH`、`EPD_CKV` | 20 MHz 級並列匯流排；實際長度目標待 WP1 介面時序，不借用 SDMMC 的 ±50 mil 規則；加焊盤會引入 stub |
| `SDMMC_CMD`、`D0–D3` | 各自與 `CLK` 長度差 ≤50 mil（1.27 mm），50 Ω ±10% single-ended，不得跨層 |

**替代方案**：以邏輯分析儀夾具直接夾元件腳位或連接器腳位，不在走線上加焊盤。`SDMMC_CLK`（TP17）
單獨保留是因為它是時序基準且只有一條，可在靠近卡座處以短 stub 引出，但**該 stub 長度須在 WP7A 規則中
明確限制**（建議 ≤2 mm，具體值待 WP3 仿真）。

這是與「探測可達性」需求的直接權衡：**訊號完整性優先於探測便利性**，高速群改用夾具而非焊盤。

### 2.5 地測試點規則

| 規則 | 內容 |
| --- | --- |
| 數量 | ≥6，分散於板面 |
| 位置 | 每個訊號測試點群旁至少一個；每個電源測試點旁至少一個 |
| 高速量測 | `SDMMC_CLK`（TP17）旁必須有地焊盤，供短接地環量測 |
| 治具 | pogo 治具區內至少 2 個地點 |

### 4.2 受控區規則（凍結）

| # | 規則 |
| --- | --- |
| H1 | 全部 HV 測試點集中在轉接板**單一連續受控區**，不分散 |
| H2 | 受控區須有絲印邊框與高壓警示標記 |
| H3 | 受控區與任何 LV 測試點、連接器、pogo 接觸面之間須有明確間距（具體間距值待 WP0 層疊與板廠規則簽核後於 WP7B 凍結） |
| H4 | HV 測試點**只**允許手動探針，**禁止**設計成 pogo 治具接觸點 |
| H5 | 探測 HV 前必須確認 EPD 下電序已完成且電容已放電；放電路徑須存在且可驗證 |
| H6 | `VCOM` 測試點須可在不破壞面板連接的情況下量測（批次 VCOM 校驗需求） |
| H7 | 核心板側**不得**有任何 §4.1 網路的測試點或走線 |

### 4.3 為何 VCOM 必須可測

PRD 多處要求批次 VCOM 證據（面板批次間 VCOM 不同，需逐批確認）。HV5 是該證據的量測入口。
但 VCOM 屬高壓域，故歸入受控區而非 §3 的 LV 區——這是 `design.md` 原文「PWR_GOOD/VCOM 測試點」
在本文件被拆分到兩個分區的原因，須明確記錄以免後續誤解為降級。
